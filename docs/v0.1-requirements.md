# Capykit v0.1 completion requirements

This page captures the current release requirements represented by the open
Capykit Linear issues as of 2026-08-28. The accepted product contract remains
[`ADR 0001`](adr/0001-product-contract.md); this page is the release-readiness
checklist for closing the final v0.1 backlog.

Canonical planning source:
[`Capykit Linear project`](https://linear.app/driftward/project/capykit-72e4a9e54d52).

## Required sequence

1. Complete host-level `driftward-host` bootstrap integration.
2. Run the cross-agent discovery pilot against the installed system.
3. Publish the validated v0.1 documentation and tagged release.

## Ownership boundary

- `driftward-host` owns host installation, PATH/config wiring, compiled catalog
  placement, smoke tests, and rollback for Driftward environments.
- Driftward-specific registry records must live outside the public Capykit
  repository and must not ship in npm, container, standalone, fixture, or
  release-note artifacts.
- Factory must not install Capykit, mutate host bootstrap state, mount private
  registry data, or receive Capykit registry credentials. Factory can only
  observe or route Capykit work through its existing Linear/GitHub workflow
  boundaries.
- The Capykit application repository owns released artifacts and product docs;
  it does not own Driftward host installation.

## Host bootstrap integration

Source issue:
[`ENG-16`](https://linear.app/driftward/issue/ENG-16/integrate-capykit-into-driftward-host-bootstrap).

Requirements:

- `driftward-host` installs and configures a pinned Capykit artifact
  idempotently.
- The compiled catalog location is discoverable from non-login shells and
  arbitrary working directories.
- Personal Hermes and Driftward Hermes runtime state remain isolated.
- Smoke tests verify discovery after bootstrap.
- Rollback documentation restores the previous host state.

This work depends on the published CLI/standalone artifacts and a private
Driftward registry source stored outside the public Capykit repository.

## Cross-agent discovery pilot

Source issue:
[`ENG-17`](https://linear.app/driftward/issue/ENG-17/run-the-cross-agent-end-to-end-discovery-pilot).

Requirements:

- The pilot covers a host shell agent, Codex, Driftward Hermes, Personal Hermes,
  and one external MCP-capable client.
- Each client resolves the same pilot records and safety metadata through the
  CLI or read-only MCP server.
- Unavailable tools are reported without false availability.
- No credential values, tokens, cookies, or private runtime state are exposed.
- Pilot findings include performance and token-overhead measurements.
- Pilot evidence includes a public-artifact audit confirming Driftward-only
  registry records and credential references are absent from public source,
  npm, container, standalone, fixture, and release-note artifacts.

The pilot may start only after bootstrap integration is complete.

## Documentation and release

Source issue:
[`ENG-18`](https://linear.app/driftward/issue/ENG-18/publish-v01-documentation-and-release).

Requirements:

- README quickstart, schema reference, registry authoring guide, and security
  model are published.
- CLI and MCP examples are validated against released artifacts.
- Migration, upgrade, and known-limitations guidance is complete.
- Changelog and release notes are complete.
- The public repository, npm tarball, container image, standalone artifacts,
  fixtures, and release notes contain no Driftward private registry records.
- npm public metadata is complete, including license, repository, bugs,
  homepage, and keywords.
- `npm publish --dry-run --access public --provenance` completes cleanly with
  v0.1 package metadata.
- `npm audit --audit-level=moderate` passes, and any remaining lower-severity
  dev-tool advisory is documented as a release exception or resolved before
  publish.
- The tagged v0.1 release is published only after the end-to-end pilot passes.
